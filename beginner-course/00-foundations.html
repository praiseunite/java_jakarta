Unit 00 · Programming from absolute zero

The original course assumes you already know Java classes, objects, interfaces and annotations. If you don’t — this unit gives you every term you’ll meet, each with a one-line picture. Skim it now; come back whenever a word stops making sense.

Goal of this unit After this page, sentences like “an enterprise bean is a class with an annotation, managed by a container on a server” should feel readable — even if you can’t yet write one.
concept

1. What is a program?

A program is a list of precise instructions a computer follows, top to bottom. A computer never guesses. If you don’t say it, it doesn’t happen.

🍳
Analogy A recipe. “Heat pan. Add oil. Wait 30 seconds. Add egg.” Swap two steps and breakfast is ruined. Code is a recipe with zero tolerance for vague steps.
concept

2. What is Java? What is the JVM?

Java is a programming language — a fixed vocabulary and grammar for writing those instructions. You write Java in plain text files ending in .java.

The computer can’t run .java text directly. Two steps turn it into something that runs:

  1. Compile — a tool called javac (the Java compiler) reads your .java file and produces a .class file full of bytecode (a compact instruction format).
  2. Run — a program called the JVM (Java Virtual Machine), launched with the java command, reads the bytecode and actually does the work.
🌍
Why a “virtual machine”? The JVM is a pretend computer that behaves identically on Windows, macOS and Linux. Write once, the same .class file runs everywhere there’s a JVM. That portability is a big reason banks picked Java decades ago and still use it.

4. The building blocks, smallest to largest


  
Variable

  
A named box that holds one value. int score = 5; makes a box called score
    holding the number 5. Later score = 6; replaces what’s in the box.


  
Type

  
What kind of value a box may hold. Common ones: int (whole number),
    double (decimal number), boolean (true/false),
    String (text, always in double quotes: "hello").
    Java checks types before running, so int x = "hello"; won’t even compile.


  
Method

  
A named, reusable block of steps — often taking some input and giving back a result.

  
// name: add   inputs: two ints   gives back: an int
int add(int a, int b) {
    return a + b;      // "return" hands the answer back to whoever called add(...)
}

  
You call it by name: add(2, 3) produces 5.


  
Class

  
A blueprint that groups related data and methods under one name. A BankAccount class
    might hold a balance and offer deposit(...) and withdraw(...) methods.


  
Object (a.k.a. instance)

  
An actual thing built from a class blueprint, created with the new keyword:
    BankAccount acc = new BankAccount();. One class, many objects — like one cookie
    cutter, many cookies. Each object has its own copy of the data.

  

    🔑
    
Remember this pair
      Class = the plan. Object = a real item made from the plan.
      Almost everything in Java is an object created from some class.

  


  
Interface

  
A promise about what methods exist, with no code for how they work. It’s a contract.

  
interface Greeter {
    String greet(String name);   // any Greeter MUST provide this method
}

  
A class then implements the interface and supplies the real code:
    class FriendlyGreeter implements Greeter { ... }. Other code can say “give me any
    Greeter” without caring which one. This is how Jakarta EE lets your code talk to a
    bean without knowing the bean’s real class.


  
Inheritance (lightly)

  
class Cat extends Animal means Cat gets everything Animal
    has, plus its own extras. You’ll mostly see this as extends HttpServlet — “my class
    is a kind of servlet”.

5. Packages & imports

  
Real projects have thousands of classes, so they’re filed into packages — like
    folders, written with dots: com.globalbank.accounts. The first line of a file declares
    its package. To use a class from another package you import it:

  
package com.globalbank.web;

import jakarta.ejb.Stateless;   // "let me use the Stateless class from jakarta.ejb"

  

    ⚠️
    
You will meet jakarta.* and javax.*
      Years ago these packages were named javax.*. Most were renamed to
      jakarta.*. A few kept the old name on purpose — javax.sql,
      javax.naming. So import javax.naming.InitialContext; is correct,
      but import jakarta.naming.InitialContext; does not exist. Unit 05 flags this.

  


  concept
  
6. Annotations — the @ things

  
An annotation is a label you stick on a class or method that some tool reads later
    to change how the code is treated. It’s not instructions that “run”; it’s a sticky note with meaning.

  
@Stateless                 // sticky note: "server, treat this as a stateless bean"
public class CalculatorBean implements CalculatorRemote {
    @Override               // sticky note to the compiler: "this replaces a method from the interface"
    public int add(int a, int b) { return a + b; }
}

  
The whole of Jakarta EE is basically: write a normal class, add a few annotations, and the
    server does the heavy lifting the annotations describe (transactions, security, pooling…).

8. Exceptions & stack traces

  
When something goes wrong at runtime, Java throws an exception — it stops the
    current work and reports an error object (e.g. NullPointerException,
    ArithmeticException). You can try { ... } catch (Exception e) { ... } to
    handle it instead of crashing.

  
The printout that follows an error is a stack trace: the chain of method calls that
    led to the failure, most recent first. Reading skill you’ll use forever:

  
java.lang.ArithmeticException: / by zero
    at com.example.CalculatorBean.divide(CalculatorBean.java:42)   <-- the real culprit line
    at com.example.Main.main(Main.java:11)
Caused by: ...                                                     <-- look here for the ROOT cause

  
Rule: scroll to the first line of your own code in the trace, and read any
    “Caused by:” at the bottom. Unit 16 practises this.


  concept
  
9. Libraries, JARs & “an API”

  
A library is someone else’s prewritten code you reuse. Java libraries ship as
    JAR files (a .jar is just a zip of .class files).

  
An API (Application Programming Interface) is the set of classes and methods a
    library offers you to call — its “control panel”. “The JMS API” means “the classes you use to do
    messaging”. You’ll hear *API* constantly; it just means *the callable surface of some component*.

11. Servers, clients, HTTP

  
A server is a program that stays running and waits for requests. A
    client is whatever sends a request (a browser, a phone app, another program).

  
HTTP is the request/response language of the web. A client sends a
    request (“GET me the page at /accounts/123”); the server sends back a
    response (some HTML or data, plus a status code like 200 OK or
    404 Not Found). Web addresses starting http://localhost:8080 mean
    “a server on this same machine, listening on port 8080” — which is exactly where WildFly runs.

  

    🏪
    
Analogy
      Server = a shop that’s always open. Client = a customer. HTTP = the language they order in.
      Port = which counter you walk up to.

12. Databases & SQL

  
A database stores data that must survive after the program stops — accounts,
    orders, users. A relational database (PostgreSQL, MySQL, H2…) stores it in
    tables: rows and named columns, like a spreadsheet with rules.

  
SQL is the language for talking to it:

  
SELECT balance FROM accounts WHERE account_id = 123;   -- read one value
INSERT INTO accounts (account_id, balance) VALUES (124, 0);   -- add a row
UPDATE accounts SET balance = 500 WHERE account_id = 124;     -- change a row

  
Your Java code sends SQL to the database and gets rows back. Units 12–13 show two ways to do that
    (raw JDBC, and JPA which hides most of the SQL).

13. The words this course leans on

  

    
WordPlain meaning

    
      
ContainerThe part of the server that creates, manages and destroys your objects, and wraps them with services (security, transactions). You don’t call new — the container does.

      
BeanJust “a class the container manages for you.” An enterprise bean is one with EJB annotations like @Stateless.

      
DeployHand your built .war/.ear to the server so it starts running it.

      
Inject“The container fills this field in for me.” You declare @Inject SomeService s; and the container hands you a ready object.

      
InstanceSame thing as an object — one concrete item made from a class.

      
TransactionA group of steps that must all succeed or all be undone. Unit 06.

      
Asynchronous“Send it and carry on; the result comes later.” The opposite of waiting (synchronous). Unit 11.
