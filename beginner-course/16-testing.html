Unit 16 · Testing & reading errors

Two survival skills the original course left out: writing an automated test so you know your logic works, and reading a stack trace so a wall of red text becomes one fixable line.

concept

Why test at all

A test is code that runs your code and checks the result. Once written, it re-checks in seconds, forever. It catches the bug you’d otherwise find in production at 2 a.m.

concept

A JUnit 5 test

CalculatorBeanTest.java
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

class CalculatorBeanTest {

    private final CalculatorBean calc = new CalculatorBean();  // plain unit test: no container

    @Test
    void adds_two_numbers() {
        assertEquals(15, calc.add(10, 5));
    }

    @Test
    void divide_by_zero_throws() {
        ArithmeticException ex = assertThrows(
            ArithmeticException.class, () -> calc.divide(1, 0));
        assertEquals("Cannot divide by zero!", ex.getMessage());
    }
}
PieceMeaning
@Test“Run this method as a test.”
assertEquals(expected, actual)Fail the test unless they match.
assertThrows(Type.class, () -> …)Fail unless the lambda throws that exception.
Arrange → Act → AssertThe shape of almost every test: set up, do the thing, check.

Run them with mvn test (try it in the terminal on any unit page), or the green ▶ next to a test method in IntelliJ.

concept

The test pyramid

LevelTestsSpeed / count
UnitOne class in isolation (like above). Mock its collaborators.Milliseconds · many
IntegrationSeveral parts together — a bean + a real database. Tools: Arquillian, Testcontainers.Seconds · fewer
End-to-endThe whole app through its HTTP API or UI.Slow · fewest

Write mostly unit tests. They’re fast enough to run on every save and pinpoint the break.

concept

Reading a stack trace — the method

  1. Read the top line: the exception type and message (what went wrong).
  2. Scan down to the first frame in your own package (com.globalbank.…) — that’s where in your code it blew up. Frames above it are library internals.
  3. Read every “Caused by:” from the bottom up. The deepest one is the root cause; the ones above are wrappers.
  4. Open that file at that line number. Fix that.
