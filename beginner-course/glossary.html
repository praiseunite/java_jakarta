Glossary

Plain-language definitions for every term this course uses. Skim it, or jump to a letter.

ABCDE FHIJL MNOPQ RSTVW

A

ACID
The four guarantees of a transaction: Atomicity (all steps or none), Consistency (no rule broken), Isolation (concurrent transactions don’t see each other’s half-done work), Durability (a commit survives crashes). Unit 06.
Annotation
A label starting with @ placed on a class, method or field that a tool or the server reads to change how the code is treated — e.g. @Stateless. Not code that runs.
API (Application Programming Interface)
The set of classes and methods a library or component offers you to call — its control panel.
Application server
A large program (here, WildFly) that contains all the Jakarta EE machinery; you deploy your app into it.
Asynchronous
“Send it and carry on; the result comes later.” Opposite of synchronous (wait for the answer). Units 04, 11.
Atomicity
See ACID. A transaction runs completely or not at all.

B

Backing bean
A Java object a Jakarta Faces page binds its components to with #{...}. Unit 09.
Bean
Any class the container manages for you. An enterprise bean carries EJB annotations (@Stateless, @Stateful, @Singleton, @MessageDriven). A CDI bean is any class CDI can inject.
Bytecode
The compact instruction format in a .class file, produced by javac and run by the JVM.
Broker (message broker)
The server that stores and routes JMS messages between producers and consumers. Unit 11.

C

CDI (Contexts and Dependency Injection)
The wiring layer that resolves @Inject points and manages how long injected objects live (their scope). Unit 14.
Class
A blueprint that groups data and methods under one name.
Client
Whatever calls a bean or sends a request — a browser, an app, another bean. Local client = same JVM; remote client = different JVM/machine. Unit 10.
Compile
Turn .java source text into .class bytecode, with javac.
Connection pool
A set of already-open database connections lent out and returned, so code never pays the setup cost. close() returns a connection rather than destroying it. Unit 05.
Container
The part of the server that creates, pools, injects, wraps (with security/transactions) and destroys your beans. Why you never call new on a bean.
CMT / BMT
Container-Managed / Bean-Managed Transactions — whether the container or your code marks transaction boundaries. Unit 06.
Correlation ID
JMSCorrelationID — a tag a reply message echoes so the sender can match it to the original request. Unit 11.

D

DAO (Data Access Object)
A class whose job is reading/writing one kind of data — hides the SQL or JPA calls behind plain methods (create, findById…). Unit 12.
DataSource
The object you ask for a database connection; a connection pool sits behind it. Injected with @Resource(lookup=…). Unit 05.
Declarative
Saying what you want with annotations/config and letting the container do it — vs programmatic (writing the steps yourself).
Deploy
Hand your built .war/.ear to the server so it starts running it.
Durability
See ACID. Once committed, changes survive any crash.

E

EAR / WAR / JAR
Package formats. JAR = a zip of .class files (a library or EJB module). WAR = a web app. EAR = an enterprise bundle that can contain several WARs/JARs.
EJB (Jakarta Enterprise Beans)
The Jakarta EE API for business-logic components — session beans and message-driven beans.
EntityManager
The JPA object you call to persist/find/remove entities and run JPQL queries. Injected with @PersistenceContext. Unit 13.
Entity (entity bean)
A persistent object mapped to a database table: a class with @Entity and @Id. Has identity (a primary key). Units 04, 13.
Exception
An error object Java throws to stop the current work and report a problem; caught with try/catch.
Expression Language (EL)
#{...} in a Facelets page — binds a component to a bean field or method. Unit 09.

F

Facelets
The XHTML file format for writing Jakarta Faces pages. Unit 09.

H

HTTP
The request/response language of the web. A client sends a request (GET /path); the server sends a response plus a status code (200, 404…).

I

Inject
The container fills a field or parameter with a ready object, so you don’t create it. @Inject (CDI) or @EJB. Unit 14.
Instance
Same as an object — one concrete item built from a class.
Interface
A contract listing method signatures with no bodies. A class implements it and supplies the code.
Isolation
See ACID. Concurrent transactions don’t see each other’s uncommitted work.

J

JAX-RS (Jakarta RESTful Web Services)
Annotations that turn Java methods into HTTP/JSON endpoints (@Path, @GET…). Unit 15.
JCA (Jakarta Connectors)
The standard socket for plugging any external system (mainframe, ERP…) into an app server via a resource adapter (.rar). Unit 12.
JDBC
The low-level Java API for talking to relational databases: Connection → Statement → execute → ResultSet → close. Unit 12.
JMS (Jakarta Messaging)
The API for asynchronous messaging via a broker — queues and topics. Unit 11.
JNDI (Java Naming and Directory Interface)
A name → object directory on the server. Look up "jdbc/GlobalBankDB" and get a real resource. Package is javax.naming (not jakarta.naming). Unit 05.
JPA (Jakarta Persistence)
An object-relational mapper: translates between Java objects and database rows so you rarely write SQL. Unit 13.
JPQL
A query language like SQL but written over entities and their fields, not tables and columns. Unit 13.
JSF (Jakarta Faces)
A server-side, component-based web UI framework; pages are written in Facelets. Unit 09.
JTA (Jakarta Transaction API)
The API the server uses to manage transactions, including ones spanning several resources (XA / two-phase commit).
JVM (Java Virtual Machine)
The “pretend computer”, launched by the java command, that runs bytecode the same way on any operating system.

L

Library
Someone else’s reusable code, shipped as a JAR.
Lifecycle
The stages a bean passes through — created, ready, (passivated), destroyed — with hooks like @PostConstruct, @PreDestroy.
Local client
A caller in the same JVM as the bean: pass-by-reference, no network. Uses @Local or no interface. Unit 10.
Lock (@Lock)
In a singleton, controls concurrency: WRITE = one thread at a time; READ = many at once. Unit 07.
Lost update
Two writers read the same value and overwrite each other; concurrency control (optimistic/pessimistic) prevents it. Unit 07.

M

Maven
The build tool. pom.xml describes the project and its libraries; mvn clean package builds it.
MDB (message-driven bean)
A bean the container invokes when a message arrives on a queue/topic. Implements MessageListener (onMessage). Units 04, 11.
Method
A named, reusable block of steps, often taking input and returning a result.
Marshalling / serialization
Turning an object into bytes to send over a network (and back). Required for @Remote arguments. Unit 10.

N

Namespace (JNDI)
java:global (whole server) ⊃ java:app (one EAR) ⊃ java:module (one JAR/WAR). Unit 05.
new
The Java keyword that builds an object from a class. You use it for plain objects, not for beans — the container makes those.

O

Object
A concrete item built from a class blueprint. One class → many objects, each with its own data.
Optimistic locking
Don’t lock; add a @Version column; fail (and retry) if someone else changed the row since you read it. Unit 07.
ORM (object-relational mapping)
Mapping objects to database rows — what JPA does.

P

Package
A dotted “folder” for classes, e.g. com.globalbank.accounts. Use one with import.
Passivation / activation
Parking an idle stateful bean to disk to save memory, then restoring it on the next call. Unit 03.
Pessimistic locking
Lock the row on read; others wait. For frequent clashes / critical data. Unit 07.
Pool
A stock of ready instances (stateless beans, DB connections) lent out and reused.
pom.xml
Maven’s project file: groupId, artifactId, version, packaging, and dependency entries.
PreparedStatement
A JDBC statement with ? placeholders — safe from SQL injection, precompiled. Always prefer it. Unit 12.
Primary key
The column/field that uniquely identifies a database row / entity (@Id).
Producer (CDI @Produces)
A method whose return value becomes injectable — for config values or objects you don’t own. Unit 14.
Programmatic
Writing the steps in code yourself (vs declarative annotations).
Proxy
A stand-in object the container gives you instead of the real bean, so it can add security/transactions/remoting around each call.

Q

Qualifier
A custom annotation that picks between multiple CDI beans of the same type (@Sms vs @Email). Unit 14.
Queue
A JMS destination where each message goes to exactly one consumer (point-to-point). Unit 11.

R

Remote client
A caller in a different JVM/machine: pass-by-value (serialized), slower, needs a @Remote interface. Unit 10.
REQUIRED / REQUIRES_NEW
Transaction attributes. REQUIRED (default): join or create a transaction. REQUIRES_NEW: own separate transaction (used for audit logs). Unit 06.
Resource
An external thing a bean uses — a database, a queue, a mail session — usually reached via JNDI.
Resource adapter (.rar)
A pluggable JCA driver connecting an app server to one external system. Unit 12.
REST
Modelling a system as resources at URLs, acted on with HTTP verbs (GET/POST/PUT/DELETE). Unit 15.
ResultSet
A JDBC cursor over query rows; advance with rs.next(). Unit 12.
Rollback
Undo every change in a transaction. In CMT, throwing an exception triggers it. Unit 06.

S

Scope (CDI)
How long an injected bean lives: request / session / application / dependent / conversation. Unit 14.
Serializable
A marker interface meaning “this object can be turned into bytes”. Required for remote arguments and session-scoped beans.
Server
An always-running program that waits for requests.
Servlet
A Java class that handles HTTP requests directly (doGet/doPost) — the low-level web component beneath JSF/JAX-RS.
Session bean
A container-managed class holding business logic. Three kinds: stateless, stateful, singleton. Unit 03.
Singleton bean
Exactly one instance for the whole app, shared by all clients; guard state with @Lock. Unit 03.
SQL
The language for reading/writing a relational database (SELECT, INSERT, UPDATE, DELETE).
Stack trace
The chain of method calls printed when an exception is thrown. Read: type/message → first frame in your package → deepest “Caused by:”. Unit 16.
Stateful bean
One instance per client that remembers its fields across calls for a conversation; ended with @Remove. Unit 03.
Stateless bean
No memory between calls; served from a pool; the default choice. Unit 03.
Synchronous
The caller waits for the result before continuing. Opposite of asynchronous.

T

Topic
A JMS destination that broadcasts a copy of each message to every subscriber (publish/subscribe). Unit 11.
Transaction
A group of steps that commit together or roll back together. Unit 06.
@TransactionAttribute
Declares how a method relates to the caller’s transaction: REQUIRED, REQUIRES_NEW, MANDATORY, SUPPORTS, NOT_SUPPORTED, NEVER. Unit 06.
try-with-resources
try (Connection c = …) { } — automatically closes the resource (returns a pooled connection) in the right order.
Type
What kind of value a variable may hold: int, double, boolean, String, a class…

V

Variable
A named box holding one value.
@Version
A field JPA uses as an optimistic-lock counter; it bumps on each update and is checked in the WHERE clause. Unit 07.

W

WildFly
The free, open-source Jakarta EE application server used in this course (formerly “JBoss AS”). Runs on ports 8080 (apps) and 9990 (admin).
Web container
The part of the server that runs servlets and JSF pages and calls your enterprise beans.
