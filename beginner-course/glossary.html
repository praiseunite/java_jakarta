Glossary

Plain-language definitions for every term this course uses. Skim it, or jump to a letter.

ABCDE FGHIJ LMNOP QRSTU VWX

A

@AccessTimeout
On a singleton, how long a thread waits for the lock before giving up instead of blocking forever. See Session 4.
ACID
The four guarantees of a transaction: Atomicity (all steps or none), Consistency (no rule broken), Isolation (concurrent transactions don’t see each other’s half-done work), Durability (a commit survives crashes). See Session 4.
Annotation
A label starting with @ placed on a class, method or field that a tool or the server reads to change how the code is treated — e.g. @Stateless. Not code that runs.
API (Application Programming Interface)
The set of classes and methods a library or component offers you to call — its control panel.
@ApplicationException / application exception
An exception your business code throws on purpose to say “this request failed”. By default the container still commits the transaction; mark it rollback = true to undo the work. Opposite of a system exception. See Session 10.
Application server
A large program (here, WildFly) that contains all the Jakarta EE machinery; you deploy your app into it.
Archetype (Maven)
A ready-made project template — folder layout plus pom.xml — that Maven copies so you do not start from an empty folder. IntelliJ’s “New → Project → Maven Archetype” uses one. See Set up your workshop.
Arquillian
A testing framework that runs an integration test inside a real Jakarta EE container, so beans, JNDI and persistence are exercised for real. See the testing unit.
Assertion
In a test, the checking line that is allowed to fail — assertEquals, assertThrows. A test with no assertion proves nothing. See the testing unit.
Asynchronous
“Send it and carry on; the result comes later.” Opposite of synchronous (wait for the answer). See Session 4 and Session 7.
Atomicity
See ACID. A transaction runs completely or not at all.
Authentication / authorisation
Authentication is “who are you?” (logging in); authorisation is “what may you do?” (which roles). Passing the first does not grant the second. See Session 13.

B

Backing bean
A Java object a Jakarta Faces page binds its components to with #{...}. See Session 5.
Bean
Any class the container manages for you. An enterprise bean carries EJB annotations (@Stateless, @Stateful, @Singleton, @MessageDriven). A CDI bean is any class CDI can inject.
Bean Validation
A Jakarta standard for putting rules on your fields (@NotNull, @Size) that the container checks automatically before your code runs; a broken rule stops the call. See Session 9.
beans.xml
A small marker file in a module’s META-INF (or WEB-INF) that tells the server CDI should be active there. See Session 11.
BOM (Bill of Materials)
A Maven entry that fixes the versions of a whole family of libraries at once, so you list them as dependencies without naming versions yourself. See Session 14.
Broker (message broker)
The server that stores and routes JMS messages between producers and consumers. See Session 7.
Browser
The program (Chrome, Edge, Firefox…) that asks a server for pages and draws the HTML it gets back — your user’s window onto the app.
Bytecode
The compact instruction format in a .class file, produced by javac and run by the JVM.

C

CDI (Contexts and Dependency Injection)
The wiring layer that resolves @Inject points and manages how long injected objects live (their scope). See Session 11.
Class
A blueprint that groups data and methods under one name.
Classloader
The part of Java that loads .class files into memory when it needs them. Each deployed app gets its own, which is why the same class name can exist twice — the cause of “loaded by a different classloader” errors. See Session 14.
Classpath
The list of places the program looks for the classes it needs — like a row of folders checked in order when you ask for a part. Maven’s provided scope keeps a library on your compile classpath but out of the finished .war. See Session 14.
Client
Whatever calls a bean or sends a request — a browser, an app, another bean. Local client = same JVM; remote client = different JVM/machine. See Session 6.
Collection
An object that holds many values at once — a List, a Set, a Map. See Foundations.
Compile
Turn .java source text into .class bytecode, with javac.
Component tree
In Jakarta Faces, the server’s live model of a page as nested Java objects — every box, button and table — held inside the FacesContext. See Session 5.
Connection pool
A set of already-open database connections lent out and returned, so code never pays the setup cost. close() returns a connection rather than destroying it. See Session 3.
ConnectionFactory
The JMS object that hands out connections to the message broker; you inject one and use it to send or receive messages. See Session 7.
ConstraintValidator
The class that implements one custom Bean Validation rule — you write the check once and reuse it through your own annotation. See Session 9.
Container
The part of the server that creates, pools, injects, wraps (with security/transactions) and destroys your beans. Why you never call new on a bean.
Context root
The URL prefix your application lives under. Deploy GlobalBank.war and it answers at localhost:8080/GlobalBank/… — that first segment is the context root. Two running apps cannot share one. See Session 14 lab.
CMT / BMT
Container-Managed / Bean-Managed Transactions — whether the container or your code marks transaction boundaries. See Session 4.
Correlation ID
JMSCorrelationID — a tag a reply message echoes so the sender can match it to the original request. See Session 7.
CRM (Customer Relationship Management)
Business software that holds everything a company knows about its customers — a classic external system (an EIS) your app connects to. See Session 8.

D

DAO (Data Access Object)
A class whose job is reading/writing one kind of data — hides the SQL or JPA calls behind plain methods (create, findById…). See Session 8.
DataSource
The object you ask for a database connection; a connection pool sits behind it. Injected with @Resource(lookup=…). See Session 3.
Declarative
Saying what you want with annotations/config and letting the container do it — vs programmatic (writing the steps yourself).
Decorator
A CDI class that wraps a bean behind the same interface to add behaviour — like an interceptor, but it may call the real method and change the result. See Session 12.
Dependency injection
Handing a class the objects it needs instead of letting it build them itself; the container does the handing. See CDI.
Dependency scope
In Maven, how far a library travels: compile (bundled in your archive), provided (the server supplies it), test (tests only). See classpath.
Deploy
Hand your built .war/.ear to the server so it starts running it.
Deployment descriptor
An XML settings file packaged with your application that declares things outside your Java code — resource names, security roles, limits — so you can change them per environment without recompiling. web.xml is the web one; application.xml the EAR one. See Session 3.
Deployment marker file
A small file WildFly writes next to your archive in deployments/ — .deployed means live, .failed means it broke. The server’s status light. See Session 14 lab.
Deployment scanner
The background part of WildFly that watches the deployments/ folder and deploys anything you drop in. See Session 14.
Destination
In JMS, the place a message is sent to and read from — a queue or a topic. See Session 7.
Dirty read
Reading data another transaction has changed but not yet committed; if that transaction rolls back, what you read never existed. Prevented by a stricter isolation level.
DLQ (dead-letter queue)
The queue a broker moves a message to after it has failed too many times, so a poison message stops jamming the real queue. See Session 8 lab.
Durability
See ACID. Once committed, changes survive any crash.
Durable subscription
A topic subscription the broker remembers, so a subscriber that was offline still receives the messages it missed. Turns a live broadcast into a podcast. See Session 7.
DTO (Data Transfer Object)
A plain object whose only job is to carry data between layers — for example a TransferRequest holding an amount and two account numbers. Fields, not logic. See the Session 10 lab.

E

EAR / WAR / JAR
Package formats. JAR = a zip of .class files (a library or EJB module). WAR = a web app. EAR = an enterprise bundle that can contain several WARs/JARs.
EJB (Jakarta Enterprise Beans)
The Jakarta EE API for business-logic components — session beans and message-driven beans.
EJBContext
The container’s handle on the current bean call: ask it who is calling and what roles they hold, or mark the transaction for rollback. Injected with @Resource. See Session 4.
EIS (Enterprise Information System)
A big established back-office system a company already depends on — SAP, CICS, a legacy database — that your app must connect to. See Session 8.
Endpoint
One addressable operation the server offers — a URL plus a verb. GET /accounts/123 is an endpoint; so is POST /transfer. See the REST unit.
EntityManager
The JPA object you call to persist/find/remove entities and run JPQL queries. Injected with @PersistenceContext. See the JPA unit.
Entity (entity bean)
A persistent object mapped to a database table: a class with @Entity and @Id. Has identity (a primary key). See Session 4 and JPA.
Environment variable
A named setting stored by the operating system that programs can read — like JAVA_HOME or PATH. See Set up your workshop.
ERP (Enterprise Resource Planning)
Large business software that runs a company’s core operations (finance, stock, orders) — another classic EIS your app connects to. See Session 8.
Event (and @Observes)
A “something happened” announcement one bean fires, which any method marked @Observes can react to — without the sender knowing the listener exists. See Session 4 and Session 11.
Exception
An error object Java throws to stop the current work and report a problem; caught with try/catch.
Expression Language (EL)
#{...} in a Facelets page — binds a component to a bean field or method. See Session 5.

F

Facelets
The XHTML file format for writing Jakarta Faces pages. See Session 5.
FacesContext
The Faces object that represents “this request, right now”; the current component tree lives inside it. See Session 5.
FacesServlet
The one servlet every *.xhtml request goes through; it drives the six-phase Faces lifecycle and is registered as the front controller. See Session 5.
Foreign key
A database column that points at the primary key of another table, linking one row to another — e.g. an order row naming its customer.
Front controller
A single entry point every request passes through before it reaches the right code — like a hotel receptionist. In Faces, that is the FacesServlet. See Session 5.

G

Generics
The < > label on a collection that says what it holds — List<String> accepts only Strings, so you never guess the type coming out. See Foundations.
groupId / artifactId
The two names Maven gives a project in pom.xml: groupId is the organisation, artifactId the project itself. Together they identify a library you depend on. See pom.xml.

H

H2 / ExampleDS
H2 is a tiny in-memory database that ships with WildFly for practice; ExampleDS is that database’s ready-made DataSource, published at java:jboss/datasources/ExampleDS. See Session 3.
HTML (HyperText Markup Language)
The text-with-tags format a browser understands and renders into a page — headings, links, forms. See Session 5.
HTTP
The request/response language of the web. A client sends a request (GET /path); the server sends a response plus a status code (200, 404…).
HTTP method / verb
The word that says what you want to do at a URL: GET read, POST create, PUT update, DELETE remove. See the REST unit.

I

IDE (Integrated Development Environment)
One program that lets you write, navigate, run and debug code — here, IntelliJ IDEA. See Set up your workshop.
Identity store
The part of Jakarta Security that looks up a user’s password and roles — often a database table. See Session 13.
Immutable
“Cannot be changed once it is made.” A record or a String is immutable, so it is safe to share.
Inheritance
A class taking on the fields and methods of a parent class and adding its own on top — class Cat extends Animal. See Foundations.
Inject
The container fills a field or parameter with a ready object, so you don’t create it. @Inject (CDI) or @EJB. See Session 11.
Injection point
The field, constructor or method parameter where the container is asked to supply an object — the spot you put @Inject on. See Session 11.
Instance
Same as an object — one concrete item built from a class.
Integration test
A test that runs several real parts together — a bean plus a real database. Slower than a unit test, but closer to reality. See the testing unit.
Interceptor
A class whose code runs around a target method — before it, after it, or both — so a cross-cutting chore (logging, timing, a security check) lives in one place instead of being copied into every method. Think of an airport security check that every passenger passes through. See Session 12.
Interface
A contract listing method signatures with no bodies. A class implements it and supplies the code.
Isolation
See ACID. Concurrent transactions don’t see each other’s uncommitted work.
Isolation level
How strictly one transaction is walled off from another’s half-done work; a stricter level prevents things like a dirty read, at the cost of speed.

J

JAVA_HOME
An environment variable holding the folder where the JDK is installed — the computer’s note of “where Java lives”. See Set up your workshop.
JAX-RS (Jakarta RESTful Web Services)
Annotations that turn Java methods into HTTP/JSON endpoints (@Path, @GET…). See the REST unit.
JCA (Jakarta Connectors)
The standard socket for plugging any external system (mainframe, ERP…) into an app server via a resource adapter (.rar). See Session 8.
JDBC
The low-level Java API for talking to relational databases: Connection → Statement → execute → ResultSet → close. See Session 8.
JDBC driver
The small library that lets JDBC talk to one particular database brand; the database’s vendor supplies it.
JDK (Java Development Kit)
The toolkit that both compiles and runs Java — the first thing to install. See Set up your workshop.
JMS (Jakarta Messaging)
The API for asynchronous messaging via a broker — queues and topics. See Session 7.
JMSContext
The modern JMS object you inject to send and receive messages; the container opens and closes the connection for you, so you don’t. See Session 7.
JNDI (Java Naming and Directory Interface)
A name → object directory on the server. Look up "jdbc/GlobalBankDB" and get a real resource. Package is javax.naming (not jakarta.naming). See Session 3.
JSON / JSON-B
JavaScript Object Notation — a plain-text format for data, easy for both people and programs to read: {"name":"Ada","balance":42}. JSON-B is the Jakarta library that converts your Java objects to and from JSON automatically, so you rarely build the text by hand. See the REST unit.
JPA (Jakarta Persistence)
An object-relational mapper: translates between Java objects and database rows so you rarely write SQL. See the JPA unit.
JPA provider (Hibernate)
The library that does the actual object-relational mapping behind the JPA API — for WildFly, usually Hibernate. See the JPA unit.
JPQL
A query language like SQL but written over entities and their fields, not tables and columns. See the JPA unit.
JSF (Jakarta Faces)
A server-side, component-based web UI framework; pages are written in Facelets. See Session 5.
JTA (Jakarta Transaction API)
The API the server uses to manage transactions, including ones spanning several resources (XA / two-phase commit).
JUnit 5
The library that finds your @Test methods, runs them and reports which passed. See the testing unit.
JVM (Java Virtual Machine)
The “pretend computer”, launched by the java command, that runs bytecode the same way on any operating system.

L

Lambda
A small function written inline, with no name of its own — e.g. the () -> … handed to assertThrows in a test. See the testing unit.
Library
Someone else’s reusable code, shipped as a JAR.
Lifecycle
The stages a bean passes through — created, ready, (passivated), destroyed — with hooks like @PostConstruct, @PreDestroy.
Local client
A caller in the same JVM as the bean: pass-by-reference, no network. Uses @Local or no interface. See Session 6.
Localhost
The name for “this very computer”. localhost:8080 means port 8080 on your own machine, not someone else’s.
Lock (@Lock)
In a singleton, controls concurrency: WRITE = one thread at a time; READ = many at once. See Session 4.
Lost update
Two writers read the same value and overwrite each other; concurrency control (optimistic/pessimistic) prevents it. See Session 4.

M

Maven
The build tool. pom.xml describes the project and its libraries; mvn clean package builds it.
MDB (message-driven bean)
A bean the container invokes when a message arrives on a queue/topic. Implements MessageListener (onMessage). See Session 4 and Session 7.
Message selector
A filter string on a JMS consumer so it receives only the messages it wants — e.g. matching a correlation ID. See Session 7.
Method
A named, reusable block of steps, often taking input and returning a result.
Mock
A stand-in object that pretends to be a collaborator, so a unit test can check one class on its own. See the testing unit.
MOM (Message-Oriented Middleware)
The general name for broker software that moves messages between programs asynchronously — what JMS talks to. See Session 7.
Marshalling / serialization
Turning an object into bytes to send over a network (and back). Required for @Remote arguments. See Session 6.

N

@Named
A CDI annotation that gives a bean a name a Facelets page can reach with #{...}. See Session 13.
Namespace (JNDI)
java:global (whole server) ⊃ java:app (one EAR) ⊃ java:module (one JAR/WAR). See Session 3.
new
The Java keyword that builds an object from a class. You use it for plain objects, not for beans — the container makes those.
No-Interface View / @Local / @Remote
How a client sees a bean. No interface or @Local means “same JVM, direct call”; @Remote means “call it across the network”. See Session 6.

O

Object
A concrete item built from a class blueprint. One class → many objects, each with its own data.
Optimistic locking
Don’t lock; add a @Version column; fail (and retry) if someone else changed the row since you read it. See Session 4.
ORM (object-relational mapping)
Mapping objects to database rows — what JPA does.

P

Package
A dotted “folder” for classes, e.g. com.globalbank.accounts. Use one with import.
Pass-by-value / pass-by-reference
Local calls pass a reference, so the bean works on the very same object; remote calls pass a copy (value), so changes the bean makes are not seen by the caller. See Session 6.
Passivation / activation
Parking an idle stateful bean to disk to save memory, then restoring it on the next call. See Sessions 1–2.
PATH
The list of folders the operating system searches, in order, when you type a command — if Java’s folder is not on it, you get “java is not recognised”. See Set up your workshop.
Persistence context
The EntityManager’s live set of managed entities and their pending changes; inside it, editing an object is enough to have it saved on commit. See the JPA unit.
Persistence unit
A named set of entities plus the connection and provider settings for one database, declared in persistence.xml. See the JPA unit.
Pessimistic locking
Lock the row on read; others wait. For frequent clashes / critical data. See Session 4.
Point-to-Point
The queue model of messaging: each message goes to exactly one consumer. Compare publish/subscribe. See Session 7.
Poison message
A message a consumer can never process and keeps failing on; cap the retries so the broker moves it to the DLQ instead of looping forever. See Session 8 lab.
Pool
A stock of ready instances (stateless beans, DB connections) lent out and reused.
pom.xml
Maven’s project file: groupId, artifactId, version, packaging, and dependency entries.
Port
A numbered door on a computer that one program listens at; WildFly uses 8080 for apps and 9990 for admin. See Session 14 lab.
Postback
A Faces request in which the user submits a page and returns to the same page, so the server restores the previous view state. See Session 5.
PreparedStatement
A JDBC statement with ? placeholders — safe from SQL injection, precompiled. Always prefer it. See Session 8.
Primary key
The column/field that uniquely identifies a database row / entity (@Id).
Principal
The container’s way of saying “this is the person making the call” — for most apps, the username wrapped in an object. Read it with getCallerPrincipal(). See Session 13.
Producer (CDI @Produces)
A method whose return value becomes injectable — for config values or objects you don’t own. See Session 12.
Programmatic
Writing the steps in code yourself (vs declarative annotations).
Proxy
A stand-in object the container gives you instead of the real bean, so it can add security/transactions/remoting around each call.
Publish/Subscribe
The topic model of messaging: each message is broadcast to every subscriber. Compare point-to-point. See Session 7.

Q

Qualifier
A custom annotation that picks between multiple CDI beans of the same type (@Sms vs @Email). See Session 12.
Queue
A JMS destination where each message goes to exactly one consumer (point-to-point). See Session 7.

R

RBAC / role
Role-Based Access Control: give each user a role (TELLER, MANAGER) and grant access to roles rather than to people. See authentication / authorisation and Session 13.
Record (Java)
A short way to declare an immutable data class: record Point(int x, int y) {} gives you the fields, a constructor and getters. Handy for DTOs and events. See Session 12.
Remote client
A caller in a different JVM/machine: pass-by-value (serialized), slower, needs a @Remote interface. See Session 6.
Request-Reply
A messaging pattern for getting an answer without blocking: the sender names a reply queue in the message and matches the reply by correlation ID. See Session 7.
REQUIRED / REQUIRES_NEW
Transaction attributes. REQUIRED (default): join or create a transaction. REQUIRES_NEW: own separate transaction (used for audit logs). See Session 10.
Resource
An external thing a bean uses — a database, a queue, a mail session — usually reached via JNDI.
Resource adapter (.rar)
A pluggable JCA driver connecting an app server to one external system. See Session 8.
REST
Modelling a system as resources at URLs, acted on with HTTP verbs (GET/POST/PUT/DELETE). See the REST unit.
ResultSet
A JDBC cursor over query rows; advance with rs.next(). See Session 8.
RMI / HTTP-remoting
One Java program invoking a method on an object in another JVM; the stub hides the network, sending the arguments across and bringing the answer back. See Session 6.
@RolesAllowed
An annotation saying only the listed roles may call a method; the container enforces it on every call. See Session 4.
Rollback
Undo every change in a transaction. In CMT, throwing an exception triggers it. See Session 4.
Root cause
The deepest “Caused by:” line in a stack trace — the original problem that everything else was a symptom of. See the testing unit.

S

Scope (CDI)
How long an injected bean lives: request / session / application / dependent / conversation. See Session 11.
SecurityContext
The Jakarta Security object you inject to ask, in your own code, who is calling and whether they hold a role. See Session 13.
Serializable
A marker interface meaning “this object can be turned into bytes”. Required for remote arguments and session-scoped beans.
Server
An always-running program that waits for requests.
Server-side rendering
The server builds the finished HTML page and sends it; the browser just draws it. What Faces does. See Session 5.
Servlet
A Java class that handles HTTP requests directly (doGet/doPost) — the low-level web component beneath JSF/JAX-RS.
Session bean
A container-managed class holding business logic. Three kinds: stateless, stateful, singleton. See Sessions 1–2.
SessionSynchronization
A stateful bean can implement it to be told when the surrounding transaction commits or rolls back, so it can keep cached data in step. See Session 10.
setRollbackOnly()
Marking the current transaction so it is guaranteed to roll back even if the method returns normally. See Session 10.
Singleton bean
Exactly one instance for the whole app, shared by all clients; guard state with @Lock. See Sessions 1–2.
SQL
The language for reading/writing a relational database (SELECT, INSERT, UPDATE, DELETE).
Stack trace
The chain of method calls printed when an exception is thrown. Read: type/message → first frame in your package → deepest “Caused by:”. See the testing unit.
@Startup
On a singleton bean, tells the container to create it when the application starts rather than on first use. See Sessions 1–2.
Stateful bean
One instance per client that remembers its fields across calls for a conversation; ended with @Remove. See Sessions 1–2.
Stateless bean
No memory between calls; served from a pool; the default choice. See Sessions 1–2.
Status code
The three-digit number a server sends back with a response: 200 OK, 404 not found, 403 forbidden, 500 server error. See HTTP.
Stub
The small local stand-in the container gives a remote client in place of the real bean; you call it and it ships the call across the network. See Session 6.
Synchronous
The caller waits for the result before continuing. Opposite of asynchronous.
System exception
An unexpected runtime failure; by default the container rolls the transaction back. Opposite of an application exception. See Session 10.

T

target/
Maven’s output folder; mvn clean package writes your built .jar/.war/.ear there. See Maven.
Testcontainers
A testing tool that starts a real database in a temporary container for an integration test. See the testing unit.
Thread
A worker inside the running program, doing one job at a time. A server keeps many running at once — that is how it serves many users together. The catch: two threads touching the same data can corrupt it, so code that behaves correctly under this is called thread-safe. Concurrency control (@Lock, transactions) exists to make that safe. See Session 4.
TLS (Transport Layer Security)
The encryption behind HTTPS; it scrambles the traffic between a browser and a server so nobody in between can read it. See Session 4.
Topic
A JMS destination that broadcasts a copy of each message to every subscriber (publish/subscribe). See Session 7.
Transaction
A group of steps that commit together or roll back together. See Session 4.
@TransactionAttribute
Declares how a method relates to the caller’s transaction: REQUIRED, REQUIRES_NEW, MANDATORY, SUPPORTS, NOT_SUPPORTED, NEVER. See Session 10.
Transaction propagation
Whether an existing transaction carries over when one bean calls another, or the call starts (or refuses) one of its own — decided by @TransactionAttribute. See Session 10.
try-with-resources
try (Connection c = …) { } — automatically closes the resource (returns a pooled connection) in the right order.
Type
What kind of value a variable may hold: int, double, boolean, String, a class…

U

Unit test
A test of one class on its own, with its collaborators replaced by mocks — fast enough to run on every save. Compare integration test. See the testing unit.
URL / URI
A URL is a web address — scheme, host, port and path, like http://localhost:8080/globalbank/. URI is the more general name for “the address of a thing”. See endpoint.
UserTransaction
The JTA object a bean uses to drive its own transaction by hand (BMT): begin(), commit(), rollback(). See Session 10.

V

Variable
A named box holding one value.
View state
The snapshot of a Faces page’s component tree that the server saves and restores on the next postback. See Session 5.
@Version
A field JPA uses as an optimistic-lock counter; it bumps on each update and is checked in the WHERE clause. See Session 4.

W

$WILDFLY_HOME / WildFly home
The folder you unzipped WildFly into; $WILDFLY_HOME/bin holds its start scripts and the admin CLI. See Session 14.
Web container
The part of the server that runs servlets and JSF pages and calls your enterprise beans.
WildFly
The free, open-source Jakarta EE application server used in this course (formerly “JBoss AS”). Runs on ports 8080 (apps) and 9990 (admin).
Wrapper class vs primitive
A primitive (int, boolean) is a raw value and not an object; its wrapper class (Integer, Boolean) is the object form, needed inside generics and collections. See Foundations.

X

XA / two-phase commit
How one transaction spans two or more resources — say a database and a message queue. A coordinator first asks every resource to prepare; only if they all say yes does it tell them all to commit. Any refusal rolls the whole thing back. That buys all-or-nothing across systems, at the cost of being slower than a single-resource transaction. See Session 8 and Session 10.
XHTML
The XML-flavoured HTML that Facelets pages are written in; unlike ordinary HTML it must be well-formed, with every tag closed. See Session 5.
