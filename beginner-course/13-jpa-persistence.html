Unit 13 · JPA — storing objects properly

Unit 04 showed the shape of an entity. This is the part the original course barely covered: actually saving, loading and querying entities with the EntityManager. JPA lets you work with objects and (mostly) forget the SQL.

↩︎
Recap An entity is a plain class with @Entity and an @Id, mapped to a database table (Unit 04). JDBC (Unit 12) is the low-level alternative where you write every SQL string yourself.
concept

What JPA is

JPA (Jakarta Persistence API) is an object-relational mapper: it translates between Java objects and database rows. You call em.persist(account); JPA writes the INSERT. You call em.find(Account.class, 42); JPA runs the SELECT and hands you an Account object. A provider (Hibernate, on WildFly) does the actual work.

concept

Three things you need

1 · An entity with real mappings

import jakarta.persistence.*;

@Entity
@Table(name = "accounts")
public class Account {

    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;                       // DB assigns it

    @Column(name = "account_holder", nullable = false)
    private String holder;

    private double balance;

    @Version                              // optimistic locking (Unit 07)
    private int version;

    // getters / setters
}

2 · A persistence unit — src/main/resources/META-INF/persistence.xml

<persistence xmlns="https://jakarta.ee/xml/ns/persistence" version="3.0">
  <persistence-unit name="globalbankPU" transaction-type="JTA">
    <jta-data-source>java:/jdbc/GlobalBankDB</jta-data-source>
    <properties>
      <property name="jakarta.persistence.schema-generation.database.action"
                value="update"/>      <!-- create/update tables from entities -->
    </properties>
  </persistence-unit>
</persistence>

It names the unit, points at the DataSource from Unit 05, and (optionally) lets JPA build the tables from your entities.

3 · An EntityManager, injected into a bean

@Stateless
public class AccountService {

    @PersistenceContext(unitName = "globalbankPU")
    private EntityManager em;              // container injects & manages it

    public Account open(String holder) {
        Account a = new Account();
        a.setHolder(holder);
        em.persist(a);                     // INSERT (inside the method's transaction)
        return a;                          // a.getId() is now populated
    }

    public Account get(Long id) {
        return em.find(Account.class, id); // SELECT by primary key, or null
    }

    public void deposit(Long id, double amount) {
        Account a = em.find(Account.class, id);
        a.setBalance(a.getBalance() + amount);
        // no save() call needed: a managed entity is flushed at commit (Unit 06)
    }
}
✦
The “managed entity” trick An entity returned by find() or persist() is managed: JPA watches it. Change a field, and at transaction commit JPA writes the UPDATE automatically. No explicit save.

JPQL — querying by object, not table

JPQL looks like SQL but names entities and fields, not tables and columns:

List<Account> rich = em.createQuery(
        "SELECT a FROM Account a WHERE a.balance > :min ORDER BY a.balance DESC",
        Account.class)
    .setParameter("min", 10_000.0)
    .getResultList();

Relationships

@Entity
public class Customer {
    @Id @GeneratedValue private Long id;

    @OneToMany(mappedBy = "customer", cascade = CascadeType.ALL)
    private List<Account> accounts = new ArrayList<>();
}

@Entity
public class Account {
    @Id @GeneratedValue private Long id;

    @ManyToOne
    @JoinColumn(name = "customer_id")
    private Customer customer;
}
AnnotationMeaning
@OneToMany / @ManyToOneOne customer has many accounts; each account has one customer.
@JoinColumnThe foreign-key column that stores the link.
cascade = ALLPersisting/removing the customer cascades to its accounts.
mappedBy“The other side owns the foreign key” — avoids a duplicate column.
