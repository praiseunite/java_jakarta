Part 2 · The Integrated Payment Dispatcher Lab

1. Qualifiers & Dispatcher Service
package com.globalbank.payments;

import jakarta.inject.Inject;
import jakarta.enterprise.context.RequestScoped;
import com.globalbank.qualifiers.Domestic;
import com.globalbank.qualifiers.International;
import com.globalbank.interceptors.Audited;

@RequestScoped
public class PaymentDispatcher {

    // CDI supplies the exact matching implementation without ambiguity
    @Inject @Domestic
    private PaymentGateway domesticGateway;

    @Inject @International
    private PaymentGateway internationalGateway;

    @Audited // Automatically intercepted for timing and security logging!
    public void routePayment(double amount, boolean isOverseas) {
        if (isOverseas) {
            internationalGateway.process(amount);
        } else {
            domesticGateway.process(amount);
        }
    }
}

Part 3 · Top 3 CDI Deployment & Runtime Pitfalls

1️⃣
Fault 1: jakarta.enterprise.inject.AmbiguousResolutionException

Symptom: Application fails to deploy: Ambiguous dependencies for type PaymentGateway with qualifiers [@Default].

Root Cause: Two or more beans implement PaymentGateway, and neither has a distinguishing @Qualifier annotation.

Fix: Create custom qualifier annotations (e.g., @Domestic and @International) and apply them to both the bean classes and the @Inject fields.

2️⃣
Fault 2: jakarta.enterprise.inject.UnsatisfiedResolutionException

Symptom: Deployment aborted: Unsatisfied dependencies for type AccountService.

Root Cause: CDI could not find any bean implementing that interface, or the module is missing beans.xml, or the bean class is missing a scope annotation under bean-discovery-mode="annotated".

Fix: Verify WEB-INF/beans.xml exists and ensure the target bean has a valid CDI scope (e.g., @ApplicationScoped).

3️⃣
Fault 3: jakarta.enterprise.context.ContextNotActiveException

Symptom: Invoking a @RequestScoped bean from a raw background thread (e.g., new Thread(...)) crashes at runtime.

Fix: Raw unmanaged Java threads have no active HTTP Request context! Use Jakarta EE Concurrency Managed Executor Service (ManagedExecutorService) or inject @ApplicationScoped singletons for background workers.
