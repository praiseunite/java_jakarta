Part 2 · Deploying via the WildFly Management CLI

Terminal Commands — Production CLI Deployment
# 1. Start WildFly Application Server in standalone mode
$WILDFLY_HOME/bin/standalone.sh

# 2. Launch the JBoss Management CLI
$WILDFLY_HOME/bin/jboss-cli.sh --connect

# 3. Deploy the enterprise application archive
deploy target/GlobalBank.ear

# 4. Verify deployment status
deployment-info --name=GlobalBank.ear

# Output should show:
# NAME              RUNTIME-NAME      PERSISTENT RUNTIME-STATUS
# GlobalBank.ear    GlobalBank.ear    true       OK
troubleshooting

Part 3 · Top 3 Deployment & Security Pitfalls

1️⃣
Fault 1: ClassNotFoundException on Shared Libraries in EAR

Symptom: An EJB or Web module crashes at startup unable to find a utility class located in the EAR.

Fix: In an EAR, shared libraries must reside inside the directory specified by <library-directory>lib</library-directory> in application.xml. Placing JARs directly in the root of the EAR will not add them to sub-module classpaths.

2️⃣
Fault 2: WildFly reports .failed with DuplicateResourceException

Symptom: Deployment scanner generates GlobalBank.ear.failed stating context root /globalbank is already registered.

Fix: An older version of the WAR or an undeployed test archive is still holding the URL context path. Execute undeploy GlobalBank.ear in the CLI or remove old archives from standalone/deployments/.

3️⃣
Fault 3: HTTP 403 Forbidden on Valid Logged-In User

Symptom: User logs in successfully, but clicking a protected button yields HTTP 403 Access Denied.

Fix: Check the role names returned by groupsQuery in @DatabaseIdentityStoreDefinition. Role names are case-sensitive: if your DB returns "teller" and your annotation expects @RolesAllowed("TELLER"), the container will deny access.

Packaging ModelChoose single Skinny WAR for microservices; multi-module EAR for complex shared enterprise suites.

    
Shared LibrariesPlaced in EAR lib/ folder and configured via <library-directory> in application.xml.

    
Deployment MarkersWildFly transitions from .dodeploy to .isdeploying to .deployed (or .failed).

    
Portable Security@DatabaseIdentityStoreDefinition eliminates vendor-specific security configurations.
