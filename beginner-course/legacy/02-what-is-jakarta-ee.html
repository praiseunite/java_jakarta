Unit 02 · What Jakarta EE actually is

Jakarta EE is a set of rules and prewritten machinery for building big, shared, long-running server applications in Java — the kind that run banks, airlines and tax offices. Its core deal: you write the business logic, the server handles the hard infrastructure.

↩︎
Recap Unit 00: a class is a blueprint, an annotation is a meaningful sticky note, a server is an always-on program, a library is reusable code with an API (its callable surface).
concept

The problem it solves

Imagine you run a shop alone: you greet customers, take payments, track stock, do the taxes, lock up at night. Fine for 10 customers a day. At 10,000 a day it collapses — you can’t personally verify every payment or hold 50 conversations at once.

A plain Java program hits the same wall. One codebase ends up doing security checks, database transactions, thread-safety, connection management and the actual business rules — tangled together, impossible to maintain.

Jakarta EE splits those apart. You write only the business rules. The application server provides the rest as services you switch on with annotations.

concept

Without vs with — the same method

A bank transfer, done the hard way:

public class BankService {
    public void transferFunds(int from, int to, double amount) {
        Connection conn = getConnection();
        conn.setAutoCommit(false);                       // start a transaction by hand
        if (!currentUser.hasRole("TELLER"))              // check security by hand
            throw new SecurityException("Access denied");
        synchronized (this) {                            // manage threads by hand
            try {
                debit(from, amount, conn);
                credit(to, amount, conn);
                conn.commit();                           // commit by hand
            } catch (Exception e) {
                conn.rollback();                         // undo by hand
            }
        }
    }
}

The same method as a Jakarta EE bean:

@Stateless
@RolesAllowed("TELLER")                 // security: the container enforces it
public class BankService {

    @TransactionAttribute(REQUIRED)     // transaction: the container starts & commits it
    public void transferFunds(int from, int to, double amount) {
        debit(from, amount);
        credit(to, amount);
        // exception thrown? container rolls back automatically.
        // concurrency? container handles it.
    }
}
✦
This is the whole idea Same business logic. All the plumbing became annotations. That trade — write plain code, declare what you need — is Jakarta EE in one sentence.
concept

The words: server, container, bean

TermPlain meaning
Application server (WildFly)A large program you run that already contains all the Jakarta EE machinery. You drop your app into it.
ContainerThe part of the server that manages your objects: it creates them, pools them, injects their dependencies, wraps them with security/transactions, and destroys them. There’s a “web container” for servlets/JSF and an “EJB container” for enterprise beans.
BeanAny class the container manages for you. An enterprise bean is one carrying EJB annotations (@Stateless, @Stateful, @Singleton, @MessageDriven).
DeployHand your built .war/.ear file to the server so it starts running it.

The container gives beans these for free: transactions, security, concurrency control, connection pooling, lifecycle management, remote access. Every one of those is a unit later in this course.

Jakarta EE is a family of APIs

“EJB” (Enterprise Beans) is just one member. Others you’ll meet:

APIDoesThis course
Jakarta Enterprise Beans (EJB)Business-logic componentsUnits 03–08
Jakarta Persistence (JPA)Store/load objects in a databaseUnit 13
Jakarta Contexts & Dependency Injection (CDI)Wiring objects together, scopesUnit 14
Jakarta Faces (JSF) / FaceletsServer-rendered web UIUnit 09
Jakarta Messaging (JMS)Asynchronous messages between componentsUnit 11
Jakarta RESTful Web Services (JAX-RS)Build REST / JSON APIsUnit 15
Jakarta SecurityAuthentication & authorisationUnit 07

A server that implements all of these to spec is “Jakarta EE certified”. WildFly is; so are Payara, GlassFish and Open Liberty. Your code moves between them without changes — that’s the point of a standard.

⚠️
Java EE vs Jakarta EE vs javax vs jakarta Same technology, renamed. It was “J2EE”, then “Java EE”, now “Jakarta EE” (since Oracle handed it to the Eclipse Foundation). With that move, most package prefixes changed from javax.* to jakarta.*. A few didn’t (javax.sql, javax.naming) — Unit 05 flags the trap.

One-line summary

Jakarta EEStandard + machinery for large server apps; you write logic, the server does infrastructure.
Application serverWildFly — contains the machinery; you deploy your app into it.
ContainerManages your beans’ whole life and wraps them with services.
BeanA container-managed class; enterprise bean = one with EJB annotations.
FamilyEJB, JPA, CDI, JSF, JMS, JAX-RS, Security — separate APIs, one platform.
